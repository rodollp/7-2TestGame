# 3D Action Roguelite

> Unity 6 기반 3D 액션 로그라이트 개인 프로젝트

---

## 프로젝트 소개

Unity 6와 C#을 활용하여 제작한 3D 액션 로그라이트 프로젝트입니다.

플레이어는 제한 시간 동안 등장하는 몬스터를 처치하며 경험치와 골드를 획득하고, 레벨업을 통해 새로운 무기를 획득하거나 기존 무기와 능력치를 강화할 수 있습니다.

전투와 성장 시스템을 구현하는 과정에서 단순히 기능을 동작시키는 것에 그치지 않고, 새로운 기능을 추가하거나 기존 기능을 수정하기 쉽도록 각 시스템의 역할을 나누는 것을 중점적으로 고민했습니다.

# 핵심 시스템

## 1. 무기 공격 시스템

처음에는 하나의 무기를 동작시키는 것을 중심으로 공격 기능을 구현했습니다.

하지만 무기 종류가 늘어나면서 공격 패턴뿐만 아니라 필요한 적 탐지 방식도 달라졌고, 하나의 공격 코드에서 모든 무기의 동작을 처리할 경우 새로운 무기를 추가할수록 기존 코드를 계속 수정해야 하는 문제가 있었습니다.

이를 개선하기 위해 공격 시스템의 역할을 나누고, 무기마다 달라지는 공격 방식에는 **Strategy Pattern**을 적용했습니다.

```text
PlayerWeaponController
        │
        ├── WeaponInventory
        │
        └── AttackStrategy
               │
               ├── SwordAttack
               │      └── TargetFinder
               │
               └── ArrowAttack
                      └── TargetFinder
```

### PlayerWeaponController

보유하고 있는 무기의 공격 타이밍을 확인하고 각 무기에 설정된 `AttackStrategy`의 공격을 실행합니다.

공통적인 공격 흐름은 이곳에서 관리하고 실제 공격 방식은 각 Strategy가 담당하도록 구성했습니다.

### AttackStrategy

무기마다 달라지는 공격 방식을 분리하기 위한 추상화된 공격 구조입니다.

새로운 공격 방식을 추가할 때 기존 공격 흐름 전체를 수정하기보다 필요한 Strategy를 추가할 수 있도록 구성했습니다.

### SwordAttack

`TargetFinder`를 통해 공격 범위 안에 있는 여러 적을 탐지하고 공격합니다.

### ArrowAttack

`TargetFinder`를 통해 공격 범위 안에서 가장 가까운 적을 찾고 해당 방향으로 Projectile을 생성합니다.

### TargetFinder

적을 탐지하는 역할을 공통으로 담당합니다.

각 공격 Strategy가 필요한 탐지 방식을 선택하여 사용할 수 있도록 구성했습니다.

이를 통해 공통적인 공격 흐름은 유지하면서 무기별 공격 방식을 분리할 수 있었고, 새로운 무기를 추가할 때 기존 공격 로직에 미치는 영향을 줄일 수 있도록 개선했습니다.

---

## 2. 적 탐지 구조 개선

초기에는 배운 내용을 바탕으로 범위 안의 적을 탐지하고 필요한 대상을 찾는 기능을 직접 구현했습니다.

이 과정에서 적을 탐색할 때마다 `GetComponent`를 반복 호출하는 구조가 몬스터 수가 늘어날수록 불필요한 연산을 발생시킬 수 있다는 것을 알게 되었습니다.

문제의 원인과 개선 방법을 확인한 뒤, 살아있는 몬스터를 `MonsterManager`에서 관리하도록 구조를 변경했습니다.

```text
Monster
   │
   ▼
MonsterManager
   │
   └── AliveMonsters
           │
           ▼
      TargetFinder
           │
           ├── FindNearestTarget()
           │
           └── FindTargetsInRange()
```

현재 `TargetFinder`는 `MonsterManager`가 관리하는 살아있는 몬스터 목록을 이용하여 필요한 적을 탐색합니다.

* `FindNearestTarget()` : 공격 범위 안에서 가장 가까운 적 탐색
* `FindTargetsInRange()` : 공격 범위 안에 있는 여러 적 탐색

이 구조를 통해 적을 탐색할 때마다 필요한 컴포넌트를 반복적으로 찾는 방식을 줄이고, 몬스터 관리와 적 탐지의 역할을 분리했습니다.

---

## 3. 데이터와 실행 상태 분리

플레이어, 몬스터, 무기 등의 기본 데이터는 `ScriptableObject`를 활용하여 관리했습니다.

```text
Data
├── PlayerData
├── MonsterData
├── WeaponData
└── WeaponLevelData
```

설정 데이터와 게임 실행 중 변화하는 상태를 분리하여 같은 데이터를 여러 객체에서 활용할 수 있도록 구성했습니다.

무기의 경우 `WeaponData`에서 무기의 기본 정보와 공격 Strategy를 설정하고, 게임 실행 중 변화하는 무기 레벨 등의 상태는 별도로 관리하도록 구성했습니다.

---

## 4. 시스템별 역할 분리

프로젝트를 진행하면서 하나의 스크립트가 여러 기능을 담당할수록 새로운 기능을 추가하거나 수정하기 어려워지는 경험을 했습니다.

이를 개선하기 위해 기능에 따라 Manager와 Controller의 역할을 나누었습니다.

```text
Game System
├── GameManager
├── GameStateManager
├── GameTimer
├── MonsterManager
├── MonsterSpawnSystem
├── MonsterSpawner
└── LevelUpManager
```

각 클래스가 담당하는 역할을 나누어 하나의 기능을 수정했을 때 다른 시스템에 미치는 영향을 줄이는 방향으로 구조를 개선했습니다.

# 구현하면서 중점적으로 고민한 부분

### 무기 확장을 고려한 공격 구조

무기의 종류가 늘어나면서 공격 방식과 필요한 적 탐지 방식도 달라지는 문제를 경험했습니다.

공통적인 공격 흐름과 무기마다 달라지는 공격 방식을 분리하고, Strategy Pattern을 적용하여 새로운 무기를 추가하기 쉬운 구조를 만들고자 했습니다.

### 적 탐지 방식 개선

적 탐색 과정에서 반복적인 `GetComponent` 호출이 발생하는 구조를 개선하기 위해 `MonsterManager`에서 살아있는 몬스터를 관리하고 `TargetFinder`가 해당 목록을 이용하도록 변경했습니다.

### 클래스 역할 분리

기능이 늘어나면서 하나의 스크립트가 여러 역할을 담당하지 않도록 데이터, 상태, 게임 진행, 적 탐지, 공격 등의 역할을 나누어 관리했습니다.

# 플레이 방법

## 실행

`GameProject/Scenes/Test` 씬을 실행합니다.

## 조작법

| 입력     | 기능             |
| ------ | -------------- |
| WASD   | 이동             |
| Space  | 점프             |
| Mouse  | 카메라 회전         |
| 마우스 클릭 | UI 및 레벨업 보상 선택 |

## 게임 진행

1. 게임을 시작하면 기본 무기를 보유한 상태로 시작합니다.
2. 등장하는 몬스터는 플레이어를 추적합니다.
3. 플레이어의 무기는 범위 내의 적을 자동으로 탐지하여 공격합니다.
4. 몬스터를 처치하면 경험치와 골드를 획득합니다.
5. 경험치가 일정량 쌓이면 레벨업 보상 중 하나를 선택할 수 있습니다.
6. 새로운 무기를 획득하거나 기존 무기 및 능력치를 강화할 수 있습니다.
7. 플레이어가 사망하면 게임 오버되며, 설정된 조건을 달성하면 게임을 클리어합니다.
