### 3. 경험치 오브(ExpOrb) 개선

기존 이동 방식

```csharp
transform.position += dir.normalized * speed * Time.deltaTime;
```

변경

```csharp
transform.position = Vector3.MoveTowards(...)
```

변경 이유

- 목표 위치를 지나치는 현상 방지
- 보다 안정적인 추적
- 향후 Object Pool 적용 시에도 안정적으로 동작

---

### 4. 경험치 오브 설계 방향 결정

게임 디자인을 다시 검토.

초기에는 빠르게 플레이어에게 흡수되는 방식을 고려했지만,

참고 게임(BALL x PIT)처럼

- 플레이어가 경험치 획득 타이밍을 조절할 수 있는 플레이

를 목표로 결정.

현재 규칙

- CollectionRange 안으로 들어오면 추적 시작
- 한 번 추적을 시작하면 계속 플레이어를 따라감
- 플레이어가 움직이면 획득을 늦출 수 있음
- 플레이어가 멈추거나 접근하면 경험치 획득

### 5. 범위 공격(AOE) 구현

AttackStrategy를 확장하여
단일 공격뿐 아니라 범위 공격도 처리할 수 있도록 구현.

구현 방식

- 공격 지점을 기준으로 범위 내 몬스터 탐색
- 범위 안의 모든 몬스터에게 데미지 적용
- AttackContext를 통해 필요한 정보 전달

장점

- 새로운 무기 추가 시 AttackStrategy만 추가하면 됨
- 근접 공격, 원거리 공격, 범위 공격을 동일한 구조에서 관리 가능
- WeaponData는 데이터만 관리하고 공격 방식은 Strategy가 담당

## 느낀 점

오늘은 기능을 추가하기보다
게임의 흐름과 책임을 정리하는 작업을 진행했다.

특히 GameStateManager가
게임 상태에 따라 카메라 입력을 제어하도록 변경하면서

"상태를 결정하는 객체"와
"실제로 동작하는 객체"의 역할을 구분하는 설계를 적용할 수 있었다.

또한 경험치 오브의 동작을 단순히 빠르게 흡수하는 방식이 아니라

플레이어가 레벨업 타이밍을 조절할 수 있는
게임 플레이 요소로 활용하기로 방향을 확정하였다.

범위 공격을 구현하면서
WeaponData는 무기의 수치만 담당하고,

실제 공격 로직은 AttackStrategy가 담당하도록 역할을 분리하였다.

이를 통해 새로운 공격 방식이 추가되어도
기존 코드를 수정하지 않고 새로운 Strategy만 구현하면 되는 구조를 만들 수 있었다.
